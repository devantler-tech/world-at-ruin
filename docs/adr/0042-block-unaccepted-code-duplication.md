# Block unaccepted code duplication

Status: accepted for #1320.

## Context

The zero-threshold MegaLinter scan remains visible but cannot block while #276
owns existing copies. At adoption source `afd354c2987d92b89156d7bd96ddc34f7172bb8a`,
jscpd 5.0.16 reports 213 clones and 2,834 duplicated lines. New copies have been
outpacing cleanup. A percentage ceiling would allow new copies to replace old
ones, and line numbers would mistake a moved block for a new copy.

## Decision

A separate required job runs the same pinned scanner and MegaLinter 10.1.0
default detection exclusions. Both scans disable Git-ignore filtering so a PR
cannot hide a tracked copy by adding an ignore rule; that argument is part of
the pinned settings hash. The adoption count remains 213 clones / 2,834 lines
under that strengthened source scope. Its structured report and console count
must agree. The existing MegaLinter warning is retained. This small parallel job
does not add work to the lint job and uses no release credentials or GitHub App.

The generated catalog identifies each clone by language, sorted repository file
pair and SHA-256 of the matched fragment. Identical identities retain occurrence
counts, so adding another occurrence cannot disappear in a set. Line offsets are
diagnostic data, not identity. Content changes can require sharing the code even
when a previous version of that block was accepted.

Every entry names the open cleanup owner #276 or gives a deliberate-copy reason.
The frozen historical save-reader copies and measurement data are deliberate;
they remain scanned and counted. The job reads the cleanup owner's live state.
Missing ownership evidence, reports or fields fail closed.

Against the actual PR base (or merge-group base), the adopted catalog can only
shrink. Adding entries or increasing occurrence counts fails even when the new
entry carries a reason. Bootstrap is allowed only against the exact adoption
revision above and the hash of its independently generated catalog. Scanner
version, detection settings and adoption metadata are
fixed; changing that policy needs an explicit reviewed policy change, never an
automatic baseline regeneration.

The producer selects Git-tracked eligible files using the pinned upstream
extension/shebang inventory and explicit detection globs, verifies readability,
regular files, UTF-8 and the scanner's size limit, and rejects inline suppression.
It copies those sources into an owned Git-free directory, omitting ignore-control
files. Thus `.ignore`, `.git/info/exclude` and user/global ignore configuration
cannot hide tracked copies. Tracked language source inside a generated/cache
directory exclusion is rejected rather than treated as cleanup. A disappearing
file, symlink, oversized source or
unreadable input fails before scanning. The independent selected-source counts
are retained with the report; analyzed counts cannot name another language or
exceed that inventory. jscpd statistics deliberately omit files below its
50-token threshold, so selected and analyzed totals are distinct. Every reported
clone must name selected files and its fragment must exist in that snapshot.
Internally consistent totals alone are not proof of a readable source scope.
The selection protocol and upstream format table are in the settings hash.

The producer starts with a fresh report directory, checks the installed version,
and bounds the scan. It accepts only successful completion or the scanner's
specific zero-threshold duplication exit, backed by a complete structured report
and matching console count. Other failures, inconsistent statistics and stale
catalog entries fail. Evidence is uploaded even when the check fails.

To reproduce it locally, install the locked scanner with
`npm ci --prefix tools/duplication --ignore-scripts --no-audit --no-fund`, then
run `bash tools/duplication-guard.test.sh` and `bash tools/duplication-guard.sh`.
The latter needs authenticated read access through `gh` for the cleanup owner;
it writes evidence below the ignored `megalinter-reports/duplication-gate`.

## Cleanup and final state

Run the catalog generator after removing copies; review the diff and commit its
removed entries with the cleanup. New entries cannot pass the base comparison.
Use the following with a fresh complete scan. Generation proposes data;
only the required check against the trusted base decides acceptance.

```sh
go run tools/duplication-guard/main.go generate \
  megalinter-reports/duplication-gate/scan/jscpd-report.json \
  .jscpd.json .duplication-catalog.json
```
Do not edit generated identities or exclude source paths to make the check pass.
The catalog is the permanent blocking policy, including deliberate copies.
The plain zero-threshold warning can leave `DISABLE_ERRORS_LINTERS` only if all
remaining copies are removed; #276 must not hide deliberate copies by path.

This gate limits duplication growth. It does not prove semantic equivalence,
replace behavioral regression tests or deliver the cleanup children of #276.
